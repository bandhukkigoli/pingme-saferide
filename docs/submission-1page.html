PingME SafeRide

Live school-bus tracking & parent alerts · pingme-saferide.vercel.app

1. Hurdles Faced

  • No always-on server. Vercel runs code only when a page asks, so there is no background worker to move the bus or send alerts.
  • Missed alerts. At demo speed the bus could cross the "bus is near" radius and arrive between two phone polls, so key alerts were skipped.
  • Duplicate alerts. Several phones polling at once could each create the same alert.
  • Slow from India. Server and database ran in the US: every 1.5 s poll crossed the world (~0.45 s of database waiting).
  • Real-phone failures. The Android app opened on the role screen and never listened, the notification permission was never asked, and one hung request on a flaky Jio network froze the screen for 16 s.
  • Alarms that would not stop. After a demo reset, an old alarm kept ringing in a background tab.
  • Unrealistic routes. The given stop order zig-zagged (16.1 km) and fixed timings made the bus "drive" at 80 km/h.
  • Privacy. Parents need live info without anyone's personal location or phone number being exposed.

2. How You Are Tackling Them

  • Bus position = a pure function of time. Every poll "catches up" the trip; a compare-and-swap step counter plus unique keys mean an alert is created exactly once, no matter how many phones ask.
  • Scan the gap, not the moment. Each poll checks the whole stretch of time since the previous one (every 0.1 sim-minute), and the stop-arrival itself also fires "arriving now" as a backup, so no alert is skipped.
  • Moved closer to users. Database in Singapore + functions in sin1, buses processed in parallel: server work per poll fell from ~300 ms to ~30 ms (measured). The bus marker now glides smoothly.
  • Tested on a real phone over USB with the web-view debugger: auto-open the child's page, fixed permission flow, 6 s request timeout with retry, and a friendly "No connection, retrying" screen.
  • Self-closing alarms: an alarm stops when its alert is gone or something newer happened; it rings until the parent answers "I'm going".
  • Real road data: compared 4 stop orders on OSRM and picked the shortest (13.8 km); ETA uses real remaining road distance ÷ measured speed.
  • Automated tests (engine, every flow on the live URL, 19 screenshots) catch regressions before each deploy.

3. What Makes Our Solution Different

  • Only the bus is tracked, never a person. No child or parent location is stored; phone numbers are always masked; all demo data is fake.
  • Action, not just a dot on a map. Parents get a full-screen alarm ("Head to the stop now, 3 min") that rings and vibrates until they answer, and the school desk sees the reply live.
  • Closes the loop on every child. RFID-style tag scans on and off the bus; a missing child blocks the trip until found, and wrong-stop drop-offs are flagged instantly.
  • One system, five roles: parent, driver/attendant, school transport desk, class teacher and admin, all live from the same data, plus stop-change requests with school approval and a route editor.
  • Works on cheap phones and weak networks: a 4 MB Android app (native heads-up alarms with a custom ringtone) or just a browser link; no login, no app-store wait, near-zero hosting cost.
